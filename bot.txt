1. PROJECT OVERVIEW & CORE BUSINESS LOGIC
--------------------------------------------------------------------------------
The application is a Telegram Bot that operates an automated referral reward network with manual Nigerian Naira (NGN) fiat bank deposit verification.

Key Financial & System Mechanics:
1. Registration / Joining Fee:
   - Cost: 1000 NGN.
   - Initial Slots Included: 5 referral slots.
   - Initial Referral Reward Rate: 50% (500 NGN total base share: 400 NGN to direct referrer, 100 NGN to indirect referrer, 500 NGN retained by protocol treasury).

2. Referral Reward Payouts:
   - Direct Referrals (Level 1): 40% (400 NGN) default share, scalable with upgrades.
   - Indirect Referrals (Level 2): 10% (100 NGN) passive reward to secondary referrer.
   - Total Base Payout = 50% (500 NGN).

3. System Upgrades:
   - Slot Upgrade: Purchase +5 additional referral slots for 500 NGN.
   - Rate Boost Upgrade: Purchase +10% payout share boost for 500 NGN.
   - Rate Boost Ceiling / Hard Cap: Maximum reward rate capped at 70% (or 7000 basis points) to guarantee protocol liquidity and prevent contract/treasury draining.

4. Unclaimed / Out-of-Slot Overflow:
   - If a referrer has 0 available slots when a referred friend deposits, 100% of the deposit fee is captured by the Protocol Treasury.
   - The system alerts the referrer that they missed a referral reward due to insufficient slots and prompts them to buy more slots.

5. Paystack Gateway Deposit & Admin Verification Flow:
   - User requests deposit (1000 NGN for activation, slot purchase, or rate upgrade).
   - Bot calls Paystack Initialize Transaction API (`https://api.paystack.co/transaction/initialize`) with `amount = 100000` (kobo), `email`, and a unique Paystack reference.
   - Bot provides the generated Paystack payment link to the user along with an inline button `[✅ I Have Paid]`.
   - When user clicks `[✅ I Have Paid]`, the bot updates the deposit status to `PENDING_ADMIN_CONFIRMATION` and dispatches an instant notification to the Admin Telegram Group / Chat.
   - Admin Notification Content:
     - User Telegram ID & Username
     - Amount Paid (₦1,000)
     - Unique Paystack Reference Code
     - Inline Buttons: `[✅ Confirm]` | `[❌ Reject]`
   - Upon Admin Confirmation:
     a) User status updated to 'ACTIVE' (if registration deposit) or user slots/rate upgraded.
     b) Referral commission computed & distributed to direct/indirect uplines.
     c) User notified immediately via Telegram message.
   - Upon Admin Rejection:
     a) Account remains 'UNPAID' / unverified.
     b) User notified that payment was rejected.

6. Withdrawals:
   - Minimum withdrawal threshold: 1,000 NGN.
   - User inputs Nigerian Bank Name, Account Number, and Account Holder Name.
   - User submits withdrawal request -> Admin receives request with [MARK PAID] / [DECLINE] buttons.

3. DATABASE SCHEMA (SQL DESIGN)
--------------------------------------------------------------------------------
Implement the database tables using MySQL (InnoDB engine, utf8mb4) with proper indexes:

1. `users` Table:
   - `telegram_id` (BIGINT, PRIMARY KEY)
   - `username` (VARCHAR, NULLABLE)
   - `first_name` (VARCHAR)
   - `status` (ENUM: 'UNPAID', 'ACTIVE', 'BLOCKED') DEFAULT 'UNPAID'
   - `referrer_id` (BIGINT, NULLABLE, FK -> users.telegram_id)
   - `slots_available` (INT) DEFAULT 5
   - `referral_rate_bps` (INT) DEFAULT 4000 (40.00% direct share in basis points)
   - `balance_ngn` (DECIMAL(12,2)) DEFAULT 0.00
   - `total_earned_ngn` (DECIMAL(12,2)) DEFAULT 0.00
   - `total_withdrawn_ngn` (DECIMAL(12,2)) DEFAULT 0.00
   - `total_referrals` (INT) DEFAULT 0
   - `created_at` (TIMESTAMP) DEFAULT CURRENT_TIMESTAMP

2. `deposits` Table:
   - `id` (VARCHAR/UUID, PRIMARY KEY)
   - `telegram_id` (BIGINT, FK -> users.telegram_id)
   - `type` (ENUM: 'ACTIVATION', 'BUY_SLOTS', 'UPGRADE_RATE')
   - `amount_ngn` (DECIMAL(12,2)) NOT NULL
   - `reference_code` (VARCHAR, UNIQUE, NOT NULL)
   - `proof_file_id` (VARCHAR, NULLABLE) -- Telegram File ID for photo/receipt
   - `sender_name` (VARCHAR, NULLABLE)
   - `status` (ENUM: 'PENDING', 'APPROVED', 'REJECTED', 'EXPIRED') DEFAULT 'PENDING'
   - `admin_notes` (TEXT, NULLABLE)
   - `created_at` (TIMESTAMP) DEFAULT CURRENT_TIMESTAMP
   - `updated_at` (TIMESTAMP) DEFAULT CURRENT_TIMESTAMP

3. `referral_payouts` Table:
   - `id` (VARCHAR/UUID, PRIMARY KEY)
   - `deposit_id` (VARCHAR, FK -> deposits.id)
   - `beneficiary_id` (BIGINT, FK -> users.telegram_id)
   - `payer_id` (BIGINT, FK -> users.telegram_id)
   - `level` (INT) -- 1 for direct, 2 for indirect
   - `amount_ngn` (DECIMAL(12,2))
   - `rate_applied_bps` (INT)
   - `created_at` (TIMESTAMP) DEFAULT CURRENT_TIMESTAMP

4. `withdrawals` Table:
   - `id` (VARCHAR/UUID, PRIMARY KEY)
   - `telegram_id` (BIGINT, FK -> users.telegram_id)
   - `amount_ngn` (DECIMAL(12,2)) NOT NULL
   - `bank_name` (VARCHAR) NOT NULL
   - `account_number` (VARCHAR) NOT NULL
   - `account_name` (VARCHAR) NOT NULL
   - `status` (ENUM: 'PENDING', 'PAID', 'DECLINED') DEFAULT 'PENDING'
   - `created_at` (TIMESTAMP) DEFAULT CURRENT_TIMESTAMP

5. `bank_accounts` Table:
   - `id` (INT, PRIMARY KEY, AUTO_INCREMENT)
   - `bank_name` (VARCHAR) NOT NULL
   - `account_number` (VARCHAR) NOT NULL
   - `account_name` (VARCHAR) NOT NULL
   - `is_active` (BOOLEAN) DEFAULT TRUE
   - `created_at` (TIMESTAMP) DEFAULT CURRENT_TIMESTAMP

STEP 4: ADMIN APPROVAL HANDLER LOGIC (`admin.js`)
When Admin clicks `[✅ Approve]`:
1. Retrieve deposit record inside a database transaction.
2. If `deposit.status !== 'PENDING'`, respond with warning "Transaction already processed."
3. Update `deposit.status = 'APPROVED'`.
4. Handle deposit type execution:
   - IF `ACTIVATION`:
     a. Set user `status = 'ACTIVE'`.
     b. Trigger `distributeReferralCommission(userId, depositId)`.
   - IF `BUY_SLOTS`:
     a. Increment user `slots_available += 5`.
   - IF `UPGRADE_RATE`:
     a. Check current rate. If `referral_rate_bps >= 6000` (60%), reject upgrade attempt or set max cap at 60% (direct) + 10% (indirect) = 70% total cap.
     b. Increment `referral_rate_bps += 1000` (+10%).
5. Notify Admin: Edit channel message to show "Approved by Admin @admin_username".
6. Notify User via Telegram: Send confirmation message that deposit was verified and features unlocked.

When Admin clicks `[❌ Reject]`:
1. Prompt Admin for optional rejection reason (or default "Payment not found in bank records").
2. Update `deposit.status = 'REJECTED'`.
3. Notify user via Telegram with reason.

STEP 5: REFERRAL COMMISSION DISTRIBUTION ALGORITHM
Function `distributeReferralCommission(payerId, depositId)`:
1. Fetch payer record to find `referrer_id` (Level 1 Upline).
2. IF `referrer_id` exists:
   a. Fetch Level 1 referrer from `users`.
   b. Check if Level 1 referrer has `slots_available > 0`:
      - IF YES:
        - Direct Rate = `referrer.referral_rate_bps` (Default 4000 = 40% = 400 NGN).
        - Direct Earned = (1000 NGN * Direct Rate) / 10000.
        - Credit Level 1 referrer `balance_ngn += Direct Earned`, `total_earned_ngn += Direct Earned`.
        - Deduct Level 1 referrer `slots_available -= 1`.
        - Record in `referral_payouts` table.
        - Send Telegram notification to Level 1 referrer: "🎉 You earned ₦400 from a direct referral! Slots remaining: X".
      - IF NO (0 slots remaining):
        - 0 NGN paid to referrer.
        - Send Telegram notification to Level 1 referrer: "⚠️ You missed a ₦400 referral bonus because you have 0 slots remaining! Tap 'Upgrades' to buy more slots."
   
   c. Check for Level 2 Upline (`referrer.referrer_id`):
      - IF Level 2 referrer exists and status == 'ACTIVE':
        - Indirect Rate = 1000 basis points (10% = 100 NGN).
        - Credit Level 2 referrer `balance_ngn += 100 NGN`, `total_earned_ngn += 50 NGN`.
        - Record in `referral_payouts` table.
        - Send Telegram notification to Level 2 referrer: "🚀 You earned ₦50 passive income from a Level 2 team referral!".

STEP 6: WITHDRAWAL SCENE & PAYSTACK TRANSFERS (`withdrawWizard.js`)
1. User clicks `💸 Withdraw`.
2. Check if `user.balance_ngn < 1000`:
   - If under threshold, cancel and notify: "Minimum withdrawal is ₦1,000. Current balance: ₦X".
3. Prompt user to select/input:
   - Bank Code / Bank Name (Select from Paystack Bank list API `/bank`)
   - 10-digit NGN Account Number
4. Perform Paystack Account Name Resolution API (`GET /bank/resolve?account_number=X&bank_code=Y`):
   - Confirm verified Account Name with user.
5. Save pending withdrawal request and deduct user `balance_ngn`.
6. Send payout alert to `ADMIN_CHANNEL_ID`:
   "💸 *NEW WITHDRAWAL REQUEST*

"
   "👤 User: @username
"
   "💰 Amount: ₦X,XXX
"
   "🏦 Bank: Bank Name (Code)
"
   "🔢 Account: 1234567890
"
   "👤 Name: Verified Account Name

"
   Inline Keyboard: `[⚡ Pay via Paystack Transfer]` | `[❌ Decline & Refund]`
7. Upon Admin clicking `[⚡ Pay via Paystack Transfer]`:
   a. Create Transfer Recipient (`POST /transferrecipient`).
   b. Initiate Paystack Transfer (`POST /transfer`).
   c. Mark status = 'PAID' and send confirmation message to user with Paystack transfer reference.
8. If Admin declines: Refund `balance_ngn` to user wallet.

5. SECURITY, ANTI-ABUSE & PRODUCTION CHECKLIST
--------------------------------------------------------------------------------
1. Database Transactions: Wrap all financial updates (balance additions, slot deductions, deposit approvals) in SQL transactions (`START TRANSACTION / COMMIT (MySQL InnoDB transactions)`) to prevent race conditions.
2. Rate Limiting: Apply `telegraf-throttler` or custom session middleware to restrict command spam (max 2 commands per second per user).
3. Self-Referral Prevention: Check that `payer_id !== referrer_id` during registration and start parsing.
4. Input Sanitization: Escape string inputs in text prompts to prevent injection attack vectors.
5. Error Handling: Enclose all bot middleware in `try...catch` blocks and set `bot.catch((err, ctx) => ...)` to ensure the bot process never crashes silently.
6. Express Health Check: Create an Express server listening on `process.env.PORT` with endpoint `/health` returning `{ status: "ok" }` for continuous uptime monitoring (e.g. UptimeRobot or Render / Railway keep-alive pinging).
7. Process Manager: Include a `ecosystem.config.js` or Dockerfile for PM2 auto-restart on deployment.
